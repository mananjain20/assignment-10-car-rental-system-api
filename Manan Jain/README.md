# Assignment 10: Car Rental & Fleet Booking System REST API

A production-ready **Car Rental & Vehicle Fleet Management REST API** built with **Node.js**, **Express.js**, and **Supabase (PostgreSQL & Supabase Auth)**.

Render Link -  https://assignment-10-car-rental-system-api-3n9v.onrender.com

---

## 1. Project Overview

The Car Rental & Fleet Booking System API enables customers to register, log in, browse available vehicles, filter fleet inventory, book rentals with automatic cost calculation, view personal booking history, cancel upcoming rentals, and complete rentals.

The API features backend **date-range collision prevention** to prevent double-booking, automatic rental duration and cost calculation based on vehicle daily rates, and status management for fleet vehicles.

---

## 2. Features

- **Authentication & Authorization**: User registration and login using Supabase Auth issuing JWT Bearer tokens.
- **Fleet Management**: CRUD operations on vehicles with strict schema constraints and category validation (`Sedan`, `SUV`, `Luxury`, `Hatchback`, `Electric`).
- **Vehicle Search & Filtering**: Filter vehicles by category, status (`available`, `rented`, `maintenance`), fuel type, and brand.
- **Vehicle Rental History**: View individual vehicle details along with associated past and upcoming rental records.
- **Booking Management**: Book vehicles with mandatory date validation (`end_date >= start_date`).
- **Date Collision Prevention**: Backend check preventing overlapping bookings (`existing.start_date <= requested.end_date AND existing.end_date >= requested.start_date`).
- **Automated Cost Calculation**: Rental days and `total_cost = rental_days * daily_rate` calculated securely on the server.
- **Vehicle Deletion Protection**: Rejects vehicle deletion requests if active or upcoming bookings exist.
- **Rental Completion & Vehicle Lifecycle**: Reset vehicle status to `available` upon rental completion.
- **Centralized Error Handling**: Standardized JSON error responses and HTTP status codes across all endpoints.

## 5. PostgreSQL Database Schema

Execute the following SQL statements in the Supabase SQL Editor:

```sql
-- Create Vehicles Table
CREATE TABLE IF NOT EXISTS vehicles (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  brand VARCHAR(100) NOT NULL,
  model VARCHAR(100) NOT NULL,
  year INT NOT NULL CHECK (year >= 1900 AND year <= 2100),
  category VARCHAR(50) NOT NULL CHECK (category IN ('Sedan', 'SUV', 'Luxury', 'Hatchback', 'Electric')),
  daily_rate NUMERIC(10, 2) NOT NULL CHECK (daily_rate > 0),
  fuel_type VARCHAR(50) NOT NULL,
  seating_capacity INT NOT NULL CHECK (seating_capacity > 0),
  status VARCHAR(20) NOT NULL DEFAULT 'available' CHECK (status IN ('available', 'rented', 'maintenance')),
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- Create Rentals Table
CREATE TABLE IF NOT EXISTS rentals (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  user_id UUID NOT NULL,
  vehicle_id BIGINT NOT NULL REFERENCES vehicles(id) ON DELETE CASCADE,
  customer_name VARCHAR(150) NOT NULL,
  customer_email VARCHAR(150) NOT NULL,
  start_date DATE NOT NULL,
  end_date DATE NOT NULL,
  total_cost NUMERIC(10, 2) NOT NULL CHECK (total_cost >= 0),
  status VARCHAR(20) NOT NULL DEFAULT 'booked' CHECK (status IN ('booked', 'active', 'completed', 'cancelled')),
  created_at TIMESTAMPTZ DEFAULT NOW(),
  CONSTRAINT check_rental_dates CHECK (end_date >= start_date)
);

-- Performance Indexes
CREATE INDEX IF NOT EXISTS idx_rentals_vehicle_id ON rentals(vehicle_id);
CREATE INDEX IF NOT EXISTS idx_rentals_user_id ON rentals(user_id);
CREATE INDEX IF NOT EXISTS idx_rentals_dates ON rentals(start_date, end_date);
```

## 11. Booking Collision Logic Explanation

To prevent double-booking the same vehicle across overlapping dates, the backend evaluates all non-cancelled rentals for the requested vehicle using interval collision math:

Two date ranges $[A_{start}, A_{end}]$ and $[B_{start}, B_{end}]$ overlap if and only if:

$$\text{existing.start\_date} \le \text{requested.end\_date} \quad \text{AND} \quad \text{existing.end\_date} \ge \text{requested.start\_date}$$

### Supabase Query Implementation:
```javascript
const { data: existingRentals } = await supabase
  .from('rentals')
  .select('*')
  .eq('vehicle_id', vehicle_id)
  .neq('status', 'cancelled')
  .lte('start_date', requested_end_date)
  .gte('end_date', requested_start_date);

if (existingRentals && existingRentals.length > 0) {
  return res.status(400).json({
    success: false,
    error: 'Vehicle is already reserved during the requested timeframe.'
  });
}
```

## 12. Rental Cost & Day Calculation

Rental durations and total costs are calculated strictly on the backend using the vehicle's `daily_rate` from PostgreSQL:

$$\text{rental\_days} = \max\left(1, \left\lceil \frac{\text{end\_date} - \text{start\_date}}{86,400,000 \text{ ms}} \right\rceil\right)$$

$$\text{total\_cost} = \text{rental\_days} \times \text{daily\_rate}$$

Client-supplied `total_cost` parameters are discarded to prevent price manipulation.

## 13. Postman Testing Workflow

Follow this sequence to test all features:

1. **POST `/api/auth/register`**: Register customer `driver@travel.com`.
2. **POST `/api/auth/login`**: Obtain `access_token`. Set Bearer token in Postman.
3. **POST `/api/vehicles`**: Add Tesla Model 3 (daily_rate: 4500).
4. **GET `/api/vehicles`**: Verify newly added vehicle is listed.
5. **GET `/api/vehicles?category=Electric&status=available`**: Test filtering query.
6. **GET `/api/vehicles/1`**: Fetch vehicle details and rental history.
7. **PUT `/api/vehicles/1`**: Update `daily_rate` to 4800.
8. **POST `/api/rentals`**: Book Vehicle #1 for `2026-05-01` -> `2026-05-05`.
9. **POST `/api/rentals` (Overlap Test)**: Try to book Vehicle #1 for `2026-05-03` -> `2026-05-07`. Expect `400 Bad Request` ("Vehicle is already reserved...").
10. **POST `/api/rentals` (Valid Non-Overlapping)**: Book Vehicle #1 for `2026-05-10` -> `2026-05-12`.
11. **GET `/api/rentals/my-bookings`**: Verify user bookings.
12. **DELETE `/api/vehicles/1`**: Attempt deletion. Expect `400 Bad Request` ("Cannot delete vehicle with active...").
13. **PATCH `/api/rentals/:id/cancel`**: Cancel the May 10 -> May 12 booking.
14. **PATCH `/api/rentals/:id/complete`**: Complete the May 1 -> May 5 booking.
15. **GET `/api/vehicles/1`**: Confirm vehicle status is back to `available`.
